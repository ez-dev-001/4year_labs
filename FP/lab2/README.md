# Лабораторна робота №2 — варіант 3

Розв'язання системи лінійних рівнянь паралельним варіантом методу Гаусса (Haskell, GHC `-threaded`).

## Як працює паралельність

Метод Гаусса з вибором головного елемента в стовпці. На кожному кроці прямого ходу `k`
рядки `k+1..n-1` оновлюються незалежно один від одного: кожен потік бере свій суцільний
шматок рядків, змінює тільки їх і лише читає рядок `k`. Тому гонок немає, і результат
побітово однаковий за будь-якої кількості потоків (це перевіряє тест).

- `parallelFor` ділить рядки між потоками (`forkOn`, кожен на своєму ядрі) і чекає
  на всіх через `MVar`. Виняток з потоку передається в основний потік.
- Зворотний хід послідовний: він займає O(n²) проти O(n³) прямого ходу.
- Матриця зберігається в `IOUArray` (незапаковані `Double`), сторонніх пакетів немає.

## Збірка й запуск (Windows)

```
ghc -O2 -threaded "-with-rtsopts=-N" -outputdir build-main Main.hs -o lab2
lab2 system.txt          розв'язати систему з файлу (потоків = кількість ядер)
lab2 system.txt 4        те саме на 4 потоках
lab2 --bench 1000        заміри часу на випадковій системі 1000×1000
```

Формат файлу: `N`, потім `N` рядків по `N+1` чисел (коефіцієнти і права частина), див. `system.txt`.
Файл — не більше 64 МБ.
Програма друкує розв'язок, нев'язку `max|Ax-b|` і час.

`--bench N` розв'язує ту саму випадкову систему (точний розв'язок — усі одиниці) на 1, 2, 4, …
потоках до кількості ядер і друкує час, прискорення та похибку. Приклад на 2 ядрах:

```
Система 1000×1000, доступно ядер: 2
потоків |   час, с | прискорення | похибка max|x-1|
      1 |    2.442 |        1.00 | 6.55e-13
      2 |    1.359 |        1.80 | 6.55e-13
```

## Тести

```
ghc -O2 -threaded "-with-rtsopts=-N" -outputdir build-test -main-is Test Test.hs -o test
test
```

`Test.hs` (59 перевірок, потребує зібраного `lab2` поруч) перевіряє:

- `parallelFor`: кожен рядок обробляється рівно один раз за будь-якої кількості потоків
  (зокрема більше, ніж рядків, і `maxBound`), виняток з потоку не губиться і не вішає програму;
- `solve`: відомі розв'язки, нуль на діагоналі, вироджені й несумісні системи, нульова матриця,
  дуже малі коефіцієнти, випадкова система 150×150 на 1…200 потоках з однаковим результатом;
- розбір файлу: CRLF, BOM з Блокнота, експонента, а також відмова на `N ≤ 0`, нечислах, комі
  замість крапки, `NaN`, `Infinity`, `1e400`, неправильній кількості чисел;
- програму цілком: вироджена система, переповнення під час обчислень, відсутній файл,
  каталог замість файлу, некоректні аргументи.

Під час перевірки знайдено й виправлено: величезна кількість потоків (`9223372036854775807`)
через переповнення давала мовчки хибну відповідь; `lab2 --bench 5001` сприймалось як файл
`--bench`; великий файл займав ~50 байт пам'яті на символ (тепер розбір на `ByteString`).

Другий раунд (пошук ін'єкцій поза тестами):

- Ін'єкція опцій рантайму: зі збіркою `-rtsopts` аргумент `+RTS -t<шлях>` записував файл за
  будь-яким шляхом, а змінна `GHCRTS` керувала програмою. Тепер `-rtsopts` прибрано, кількість ядер
  задана при збірці (`-with-rtsopts=-N`).
- Файл з `0x1F 0o17` мовчки читався як шістнадцяткове й вісімкове числа, `(1)` — як 1:
  `readMaybe` приймає синтаксис Haskell. Тепер приймаються лише десяткові числа.
- Число з мільйона цифр розбиралося секунди й цілком потрапляло в повідомлення про помилку.
  Тепер довжина обмежена 64 символами, у повідомленні — перші 40.
- Фаззинг 1000 випадкових файлів: жодного падіння. Знайдено одне: нев'язка біля 1e308
  переповнювалась і друкувалась як `Infinity` при правильному розв'язку — тепер рахується в масштабі.
